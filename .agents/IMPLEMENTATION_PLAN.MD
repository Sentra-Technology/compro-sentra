# Implementation Plan: Sentra Technology Next.js Migration

## Mode

PLANNING

## Goal

Convert the current in-browser React/Babel prototype into a production Next.js App Router website while preserving the existing design, copy, layout, section order, component behavior, animations, and assets.

## Source Of Truth

The current source files are under `.ref/`.

- `.ref/Website.html`
- `.ref/website.css`
- `.ref/components/primitives.jsx`
- `.ref/components/web-*.jsx`
- `.ref/assets/`

Files explicitly ignored by `INSTRUCTION.MD` will not be ported:

- `.ref/Sentra Compro.html`
- `.ref/Sentra Compro-print.html`
- `.ref/Website v1.html`
- `.ref/Website v2.html`
- `.ref/Website v3.html`
- `.ref/styles.css`
- `.ref/tweaks-panel.jsx`
- `.ref/components/pages-*.jsx`
- `.ref/uploads/`

## Proposed Stack

- Next.js App Router at the repository root.
- JavaScript/JSX first, not TypeScript, to keep this migration close to the current prototype and reduce conversion risk.
- Global CSS via `app/globals.css`, copied from `.ref/website.css` without class renames.
- Google Fonts via Next metadata/head links or `next/font`, preserving Inter, Space Grotesk, and JetBrains Mono.

## Implementation Steps

1. Scaffold the Next.js app structure at the repository root.
   - Add `package.json`, Next/React dependencies, app scripts, and standard project config.
   - Add `app/layout.jsx`, `app/page.jsx`, and `app/globals.css`.
   - Keep the existing `.ref/` prototype files intact as migration sources.

2. Copy global styles verbatim.
   - Copy `.ref/website.css` to `app/globals.css`.
   - Import it once from `app/layout.jsx`.
   - Avoid CSS modules and avoid class name changes.

3. Copy production assets.
   - Copy `.ref/assets/` to `public/assets/`.
   - Do not copy `.ref/uploads/`.
   - Update JSX image paths from `assets/...` to `/assets/...` where needed.

4. Port shared primitives first.
   - Convert `.ref/components/primitives.jsx` into `components/primitives.jsx`.
   - Replace `Object.assign(window, ...)` with named exports.
   - Export `SentraLogo`, `SentraMark`, `CircuitOrnament`, `PageHeader`, `PageFoot`, `SectionChip`, `Icon`, `HexPattern`, and `Placeholder`.

5. Port website section components.
   - Convert each `.ref/components/web-*.jsx` file into `components/*.jsx`.
   - Add explicit imports for React hooks, primitives, and cross-component dependencies.
   - Remove all `Object.assign(window, ...)` global registration.
   - Preserve content and component structure.

6. Build the root page composition from `.ref/Website.html`.
   - Compose sections in this order:
     - `Nav`
     - `Hero`
     - `ClientLogos`
     - `About`
     - `CCTV`
     - `Services`
     - `ProductShowcase`
     - `Partnership`
     - `Portfolio`
     - `Team`
     - `FAQ`
     - `Contact`
     - `Footer`
     - `WhatsAppWidget`
   - Add the three `.bg-orb` elements and the `#scrollBar` element.

7. Move browser bootstrap effects into a client component.
   - Add `components/RootEffects.jsx`.
   - Port scroll progress, mouse-follow gradient, and reveal-on-scroll `IntersectionObserver`.
   - Mount it from the root page.

8. Preserve metadata and language.
   - Set `lang="id"`.
   - Port title and meta description from `.ref/Website.html`.
   - Preserve responsive viewport behavior.

9. Handle known prototype-only behavior deliberately.
   - Keep the contact form's current `setSent(true)` behavior for parity unless a backend/email target is provided.
   - Review the footer `Company Profile` link, because the linked deck is intentionally ignored and would otherwise become a dead production link.

10. Verify locally.
   - Install dependencies.
   - Run lint/build checks available in the Next project.
   - Start the dev server.
   - Check the browser console.
   - Manually validate desktop/mobile rendering, animations, section anchors, theme toggle, language menu, product tabs, FAQ, contact form, and WhatsApp widget.

## Risks

- The current components depend on implicit browser globals; import/export conversion is the main migration risk.
- Several components use browser-only APIs such as `window`, `document`, `localStorage`, `IntersectionObserver`, and `window.open`; these must stay in client components.
- Asset path changes can break images if any relative path is missed.
- The CSS is large and global; accidental class renames or selector scoping would break layout.
- The footer company profile link currently points at an ignored HTML deck.
- Contact form submission is not production-ready without a real endpoint.

## Assumptions

- The production app should live at the repository root, with `.ref/` retained as the source prototype/archive.
- JSX is acceptable for the first migration pass.
- Design parity is more important than refactoring.
- No backend/email service is available yet for the contact form.
